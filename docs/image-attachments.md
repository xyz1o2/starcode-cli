# 图片附件与视觉辅助

主输入框支持 Ctrl+V；终端截获该组合键时可用 Ctrl+Alt+V。剪贴板图片显示为 `[Image #N]`，提交时作为真实图像内容发送，而非本地 Markdown 路径。

- 支持 PNG/JPEG。剪贴板图片先缩放到最长边 2000 像素，编码后最多 5 MiB；每条消息最多 8 张。
- 删除输入框里的图片占位符即可取消附加。普通 Markdown 图片路径不会触发文件读取或上传。
- 图片内容随会话历史保存。撤回成功和失败回合重发都保留附件，不依赖原剪贴板临时文件。
- 读取失败、离线、未选模型或图片与命令混用时保留草稿。
- 在确认卡中粘贴图片，会将图片存入主输入草稿并提示；回答确认卡后再作为普通消息发送，确认答案本身仍是文本。

## 原生视觉模型

OpenAI Chat Completions 使用 `image_url` 数据 URI，Anthropic Messages 使用 Base64 `image` 块。模型是否接受图像由所选 provider/model 决定。没有视觉辅助配置时按原生多模态发送；不支持的模型通常会拒绝请求，此时可切换视觉模型重发。

## 纯文本模型

显式配置 `STAR_VISION_BRIDGE`，值为 JSON 对象：键是精确的 `provider-id/model-id`，值是**同一 provider、同一端点**上可接收图像的模型 ID。例如：

```bash
export STAR_VISION_BRIDGE='{"local/text-model":"vision-model"}'
```

也可以放在已有 settings 的 `env` 对象内。未提供 provider ID 时使用 `default/model-id`。模型名包含 `/` 时完整保留，如 `gateway/vendor/text-model`。

匹配该配置后，图片和当前消息的问题先发送给视觉辅助模型；其观察文字会标明来源，再交给纯文本主模型。视觉调用复用当前 provider 的地址和密钥，不会选择新服务。用户应确保所填视觉模型确实支持图片。

视觉请求有 120 秒超时，失败不会清除历史原图；成功描述在 client 内按端点、视觉模型和消息内容缓存，最多 32 条，避免工具循环反复识图。原图仍随历史保留，以支持后续切模型和重试。视觉描述可能遗漏细节，并不等于主模型直接看到了图片，也不是仅做 OCR。

## 流式空闲超时

默认连续 120 秒没有 provider 事件时结束等待；可通过 `STAR_STREAM_IDLE_SECS` 设置正整数秒数。显式设置的 30 秒仍然是 30 秒。此阈值是事件间隔，不是整个回答的总时长。

空闲超时显示为 `Stream Timeout`，与 DNS/连接失败分开。退避重试预算耗尽后保留原始超时原因，不再进入“无法分类的断流”第二套恢复阶梯。提高阈值可以容纳推理或网关缓冲，但不能修复服务端长期无响应。
