4. **P2，已确认：任务详情空态不区分思考/等待/失败。** `src/agent/subagent/runner.rs:240-279` 的进度追踪侧重完整文本和工具事件；`src/ui/components/chat_history.rs:421-479` 不显示最近工具信息和 tokens，只在没有子条目时显示等待首工具。即使任务仍在思考或网络等待，也像完全没开始；失败情形见 1（R-27）。建议基于真实状态显示 `正在等待模型响应` / `等待首个工具调用` / `执行失败`，并展示最后一次已知进度。

## Exa 资料核对

- Codex 剪贴板源码：https://github.com/openai/codex/blob/main/codex-rs/tui/src/clipboard_paste.rs 。文件列表、位图、WSL PowerShell 桥属于读取层；源码明确在后续序列化阶段读取文件并编码成图像内容。
- WSL 按键问题：https://github.com/openai/codex/issues/6793 。社区报告 Ctrl+V 可能被终端截获；Ctrl+Alt+V 可作为备用入口，具体终端仍需实测。
- OpenCode 附件文档：https://opencode.ai/docs/attachments/ 。图像以 image media 发送，需模型支持；文件体积与 Base64 编码体积是不同限制，不能直接混用。
- 社区视觉桥：https://github.com/martinmose/opencode-vision-bridge 。可参考显式视觉模型先生成描述、文本主模型继续推理的流程；不采用其默认外部服务或按整个 provider 判断视觉能力的规则。
- PaddleOCR MCP：https://www.paddleocr.ai/v3.5.0/en/version3.x/deployment/mcp_server.html 。提供本地/自托管 OCR 与文档解析；普通 OCR 的文字提取不能代替截图布局、颜色和图形理解。

附件接线要求：在 Enter 清空 paste_segments 前提取用户明确附加的图片；附件随普通消息、steering、撤回和历史保存/恢复传递，连续 user 合并时保留附件；按 provider + model 能力选择原图或已配置视觉辅助模型。不能从任意 Markdown 路径自动读取文件。该链路已于 2026-11-16 接通；视觉能力采用显式 provider/model 映射，未配置时原生发送，不做厂商级猜测。
